## Boundaries
V7 extends existing V3 storage_operation with SCAN_UPLOAD, not another queue. UploadCompletion is an internal command using current SecuredFiles UPLOAD_TRANSFER authority and exact initiating session. JdbcUploadScan rechecks local grant and locked pin, requires V6 matching evidence, enqueues one operation keyed by session and atomically moves PENDING/INITIATED to VERIFYING/VERIFYING with required intents. Repeated open requests return the same operation; terminal status read through existing metadata/session API. No public completion route or caller-supplied scan verdict. No new handle/reissue. Session expiry stays the original deadline. Existing state projections rehydrate persisted states, including actual scan evidence; no inference of clean verdict. API response fields unchanged; logical status enums documented.

UploadScanWorker.runOne explicitly claims one existing operation with bounded concurrency and lease. Job load matches exact tenant/file/version/location/session/operation and live claim token, reads V6 evidence and current backend pin. No provider or scanner I/O under DB transaction. Resolve exact backend and credentials; HEAD checks length, GET passes bounded measuring stream to trusted ContentScanner. Scanner must consume entire stream synchronously (no retention); SHA-256 computed independently of scanner, checked against V6 digest and optional provider digest; extra/short bytes, wrong hash or premature clean fail. Explicit max bytes/buffer and cooperative deadline limited by lease. Scanner returns CLEAN, MALICIOUS or UNAVAILABLE and detected MIME; no default clean implementation. Isolated conservative policy requires exact declared/detected MIME for CLEAN, nonempty bounded MIME; actual MIME normalization/allowlist/archive and scanner behavior #32/#16 pending. Synthetic verdict fixtures cannot establish production security. Real scanner must honor deadline, resource and archive budgets; blocking transport/scanner calls need actual deployment bounds.

Commit only while same claim still owns lease and session has not expired; clean rechecks local grant under lock. Trusted worker identity explicitly supplied by composition; no persisted bearer or external identity in job. Worker acts on accepted durable command, not on a fresh end-user IAM token; live revocation semantics and service identity remain #17–#19/#43 decisions. Finish job and insert immutable exact-content scan evidence plus both state transitions and audit/event intents in one transaction. CLEAN -> AVAILABLE/COMPLETED, MALICIOUS -> QUARANTINED/FAILED, invalid bytes/MIME -> FAILED/FAILED, expired -> FAILED/EXPIRED. Retry scanner unavailable/provider error; exhausted attempts dead-letter, explicit tenant/session reconcileDead records failed/expired and never makes available. If final transaction fails, no success/ack, lease recovery. Stale workers cannot commit after reclaim; they may have read bytes before losing lease. No automatic dead-letter sweep/scheduler, cleanup/delete, retry upload or production worker readiness. No quota reservation/commit (#33), no download endpoint or availability claim beyond isolated lifecycle (#35), no live deployment. Unversioned create-only service storage and no out-of-band changes assumed; scan evidence is exact bytes at scan time, not a guarantee against later mutation.
