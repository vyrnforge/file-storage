## Contract and authority
GET /v1/files?limit=50&afterFileId=... (1..100, default 50) returns items (existing logical metadata projection) and nextAfterFileId (null at end). Cursor is an already public file ID, not a capability or hidden row identifier; no provider key. Bytewise C-collation keyset order; fetch limit+1 from authorized records only. No offset, unbounded page, hidden-record cursor or total count. Unknown/duplicate parameters denied. GET /v1/usage returns five version-state buckets with fileCount, declaredBytes and availableBytes; byte sums decimal strings to preserve exact PostgreSQL numeric sums beyond signed 64-bit/JavaScript safe integer limits. Counts are logical active files visible to this caller, not whole tenant by default; declared bytes include pending, failed and quarantined declarations; availableBytes counts clean available observed bytes only. No provider billing, physical usage, reservation, quota or cleanup claims.

V10 adds LIST_METADATA independent of READ_METADATA/READ_SESSION/UPLOAD_TRANSFER/DOWNLOAD_TRANSFER; explicitly grants listing and visible usage for a purpose with OWNED_FILE or EXACT_FILE. No implicit per-file GET or byte permission. SecuredFiles verifies bearer, tenant binding, membership, entitlement, action and current trusted grants for every request. Bounded trusted scope (256 catalog grants, 4096 total returned; existing grant adapter may have lower cap); fail closed on source failure or no catalog grant. JdbcCatalog intersects trusted current grant scope with local active grant predicates before pagination/aggregation; owner actor/application and exact file/purpose/tenant checked; EXISTS avoids duplicate rows on overlapping grants. Query uses explicit tenant and immutable request owner, excludes non-ACTIVE files, no locator in projection. Same repeatable-read DB transaction per request, query timeout 5s; no external calls inside SQL. Fresh authorization and snapshot per page, not stable across updates/inserts/deletes or grant changes. Check-time external revocation race remains; no cross-system transaction. Local grants are read in query snapshot, not locked for read-only response. Aggregate scans the authorized scope with timeout, no claim of constant work/production capacity; materialized accounting, tenant-admin wider permissions and quota #33 separate. Current one-version/session schema assumption; later versioning/deletion design must update projection. No direct provider I/O or placement change.
