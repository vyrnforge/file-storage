## Explicit operational composition

StagingRuntimeApplication.start(trustedConfiguration,args) imports StagingRuntimeConfiguration, with existing API, upload/download command and transfer HTTP routes. The ordinary executable remains health-only. Trusted configuration must supply ApiRuntimeDependencies and StagingRuntimeDependencies; no environment-only bootstrap or default credentials, scanner, permissive IAM or transport. Explicit COMBINED, fs.require-separated-roles=true, fs.staging.enabled=true and bounded fs.staging.delay-ms required. Eleven distinct expected database logins (A14 ten plus DISPATCHER); same-target admission and read-only migration validation, no owner fallback. Dispatcher uses KernelDataSource to bind fs_kernel and existing Kernel v0.3.2 publisher. COMBINED health ready only with staging composition and live dependency probes. A14 legacy COMBINED stays DOWN.

One fixed-delay scheduler (100–3600000 ms), one recovery, verification and scan attempt per tick, non-overlap in process, durable leases across processes, bounded dispatcher batch 1–100. Gate each tick on roles/authority/external probe. Dispatcher default disabled; separate explicit flag after replay/reconciliation approval. Transport deadlines and DB connection/socket limits are operator responsibilities; readiness is not cancellation of in-flight calls or a request filter. Recovery records HOLD; no deletion/cleanup/migration worker registered. No historical backfill, quota/retention activation or legal-hold release.

Staging provider pin matches exact backend/location/target/reference; registry resolves persisted revision, requires ACTIVE/DRAINING and validated, no latest or alternate credentials. Only approved exact reference can resolve; exact persisted location checked before adapter opens. Gateway wrapper permits exact locator create-only upload/get/head, worker read-only get/head; deny delete/list and optional operations. Trusted factories and provider account policies must separately enforce no delete/migrate permissions; wrapper cannot constrain malicious trusted code. Both existing S3/native OSS adapters included in packaged runtime, factories/credential resolver supplied by reviewed deployment code, not arbitrary runtime plugins. No actual staging credentials, endpoints, provider traffic or deployment in A15.
