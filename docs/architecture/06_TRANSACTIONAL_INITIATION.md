# FS-120B1 — Transactional initiation

Scope: next bounded slice after PR #11 merged at b4a421dde33fc712a884f83b515719ef62d1c5be. Owner reported merge after recommendation to continue. Kernel v0.3.2 published JDBC artifact, no kernel repository edits. No HTTP, real IAM, cloud I/O or deployment.

## Contract
- Service schema fs V1 unchanged. Kernel JDBC V1–V3 run explicitly in fs_kernel using Flyway separate schema/history and classpath:db/migration. Same physical database; no separate commit for aggregate and result. Trusted DataSource supplies fresh auto-commit connections; Kernel wrapper sets schema and isolation before SQL. Production pool reset/roles, migration orchestration and backup are later gates.
- Initiate verifies caller permission before lease acquisition. Tenant+operation+derived key scoped by actor and consuming application as in existing initiation_request; SHA-256 of versioned length-prefixed fields. Fingerprint includes tenant, actor, app, purpose, name, size, declared MIME, request key. No raw bearer or provider information. No cross-tenant fallback. Configured positive lease TTL (test 10 min, no production default).
- Kernel begin returns ACQUIRED, REPLAY, IN_PROGRESS or CONFLICT. ACQUIRED executes application callback on supplied Kernel transaction connection at repeatable-read; writes aggregate and completion result atomically via executeIdempotent. No separate complete. Store only session UUID, not cached response. If rollback, abort own active lease; if abort fails expiry handles recovery. No automatic retry. Concurrent in-progress is a neutral code; caller retry required. SQL/Kernel failures neutral, no raw exception detail.
- REPLAY invokes a separate read-only application callback: require current initiation and session authorization, match original request, read current state and expiration, compare stored session UUID. No new record when aggregate missing. No new placement or grant on replay. Existing request uniqueness remains beyond Kernel lease expiry: reacquired key with same request replays original aggregate; different request conflicts. Future retention/expiry policy must reconcile both layers. No claims of exactly-once external bytes.
- Application port retains default in-memory transaction path for synthetic tests; JDBC implementation overrides initiate. Existing secured facade receives Transactions; no new public route. No audit/event intents submitted yet (FS-120C); release requires atomic required intents before public mutation exposure.
