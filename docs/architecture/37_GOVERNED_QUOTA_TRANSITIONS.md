## Reviewed policy values and transitions
V18 adds immutable quota draft/review keyed by tenant and existing retention revision. Exact expected active revision, positive limit and evidence TTL (1..86400 engineering bound) are recorded before independent review. Retention draft must be latest and mode CHARGE_UNTIL_VERIFIED_PURGE. Quota author and reviewer differ; activator differs from both quota and retention authors/reviewers. Activation loads exact immutable values, then rechecks expected active revision, reviewed values, latest retention draft, actor and timestamps, monotonic retention and capacity under the same tenant fence. DB guard runs after V17 fence and rejects mismatched direct inserts. Old reservations keep their original policy revision and settle using exact verified evidence. No quota limit/TTL default or production role. All new activations, including initial activation and non-integrated tenants, require V18 review. Existing V16/V17 activations remain immutable history; new integration enablement requires the current activation to be reviewed, so legacy non-integrated tenants must first activate a new reviewed revision. Existing enabled tenants may retain old pinned reservations; every replacement is reviewed. No historical rows are altered. No live enablement path.

## Contention and privilege boundary
V17 durable tenant fence retains repeatable-read protection. V18 function-local lock_timeout=2s bounds advisory and row lock waits inside touch_quota_fence; lock conflict maps to neutral CONFLICT and retry with the same idempotency key. Existing lifecycle/activation lock ordering remains; no provider I/O in transaction. This is not a throughput SLO, global transaction timeout or deadlock-proof guarantee. Every initiation still touches the tenant fence. V18 revokes PUBLIC access on new governance tables and execute on fence and new guard functions; invoker rights only. Explicit production application roles/grants, including any execute permission needed for the fence, require migration and deployment review. Disposable read-only role test does not imply RLS or production role isolation; trusted application writer tests use fixture DB owner. Privileged owner can bypass triggers. No production grants are installed.

## Durable reconciliation findings
Authorized isolated actor captures one SQL snapshot: current policy revision (nullable), integrated flag, missing/mismatched ledger rows, untracked versions, uncertain terminal sessions and dry-run candidate bytes. Missing rows classify only exact durable metadata: clean completed available with matching scan size -> candidate charge; pending/initiated or verifying/verifying -> candidate reserve; failed/expired with failed version, terminal recovery evidence and no claimed write -> candidate release; otherwise unresolved. Candidate sums are arbitrary precision; missing or mismatched evidence is not provider truth. Snapshot and audit/outbox atomic, immutable; independent review records ACKNOWLEDGED or NEEDS_INVESTIGATION only. Tenant-bound read; no repair or backfill commands, no provider calls. Findings are historical snapshots, not a current authorization or per-object executable plan.
