## Contract
Explicit opt-in POST /v1/files/{fileId}/versions/{versionId}/download-handle with {} returns 200 {handle,expiresAt}, no-store, no locator/credential/redirect. Uses shared metadata admission, strict JSON and neutral errors in API/COMBINED role. DOWNLOAD_TRANSFER is a distinct grant/binding action, not inferred from metadata, session or upload. OWNED_FILE requires exact owner actor/application; EXACT_FILE supports an explicitly granted other actor, scoped to tenant, application and purpose. Version must be AVAILABLE, upload COMPLETED and file ACTIVE. Current external identity, membership, entitlement and grant checked on issuance and claim; local grant locked in same database transaction. No production IAM binding defaults. Handles use 256-bit randomness, SHA-256 digest only, explicit TTL <=1h, no upload session expiry restriction for completed versions. Single-use, exact tenant/actor/app/action/version/placement/size/digest, immutable binding and monotonic claimed_at, atomic claim with logical audit/event intents. New download handle may be issued under current authorization; no replay of raw proof. V9 migration and repeatability. Handle retention/rate limits and outstanding handle quota remain #16/#33/#43 gates.

## Exact bytes
JdbcDownloadTransfers requires original immutable V5 claimed pin, V6 matching evidence, V7 CLEAN exact digest/size and successful scan operation, current ACTIVE/DRAINING validated backend revision; denies drift. No latest policy/revision substitution. No provider I/O in transaction. DurableDownloadAuthority.combine selects one action-specific authority, no fallback. Existing GET /transfer/v1/download, Authorization Bearer and X-Transfer-Handle, bounded streaming, safe generic attachment, no Range or redirect. For durable download instruction SHA-256 is measured during output; final chunk withheld if digest or size mismatches, zero-size checked before response length. A committed stream cannot be rolled back: earlier chunks may have reached the caller before final hash failure; this detects incomplete/corrupt transfer, not preventive scanning of out-of-band changes. Immutable create-only service writes and deployment storage isolation remain prerequisites; no claim of protection against arbitrary privileged storage mutation. Existing synthetic transfer tests retain optional digest compatibility; actual durable authority always supplies digest. No download completion receipt, per-byte revocation/cancellation, physical deletion/purge or migration feature. Reauthorization is check-time; no external IAM transaction across streaming.
