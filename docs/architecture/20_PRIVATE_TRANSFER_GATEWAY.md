## Design
- Separate runtime.transfer package and opt-in TransferHttpConfiguration. TRANSFER or COMBINED only; API/WORKER reject startup with transfer configuration. Default executable health-only, loopback. Combined still not ready until transfer/worker readiness is implemented. One product/metadata authority, no separate persistence authority or SDK imports in runtime. Runtime depends directly on provider SPI; provider implementations remain confined to adapter modules.
- PrivateTransferGateway takes explicit TransferAuthority, TransferProviderResolver, TransferLimits, Clock. No defaults for production size/concurrency/time. Authority contract: authenticate bearer proof (not handle alone), resolve authoritative tenant/actor/application, recheck action/resource/state/placement and current grant/revocation, atomically consume exact opaque single-use handle, return immutable internal TransferInstruction. Expired, wrong action, replay, mismatch and authority outage deny. Instruction binds tenant/actor/application/action/file/version/session/backend/config revision/location/object key/exact size/expiry; upload requires session and no provider version. Gateway checks action/expiry/size before resolver. No client-supplied actor, tenant or physical placement. The actual durable issuance/claim transaction and IAM/control-plane adapter are not implemented here. Synthetic fixture is process-local and must never be deployed.
- Resolver contract: exact authorized persisted pin only, no latest or alternative fallback, close credential/client lease; gateway passes exact locator to provider. No network I/O in metadata transaction. Real resolver integration with JdbcRegistry.resolveExisting and adapter factory, including download pin semantics, is follow-up work. Provider error mapped to neutral code without raw cause.
- PUT /transfer/v1/upload and GET /transfer/v1/download, bearer + X-Transfer-Handle (sensitive, no URL/query/log). PUT application/octet-stream, content length optional; declared size if present must match instruction. Adapter SPI owns exact-size/create-only and bounded spooling, never overwrite. GET bounded buffer, exact count, extra-byte check before final chunk; closes provider stream and lease, never closes caller output. No range/resume, multipart, direct presign, redirect or content verification claim. HEAD rejected without claim. No-store; safe octet-stream attachment. Errors before commitment neutral JSON; after commitment abort without JSON (container behavior/partial client receipt still requires real transport evidence). Successful PUT 204 means provider accepted staged bytes, not file availability, scan or durable completion. A claimed handle stays consumed after failures; reissue/reconcile exact target under #31/#35, no automatic retries.
- Nonblocking semaphore bounds concurrent work including authority/resolver. Oversized declared input and busy rejected before claim; invalid exact size may consume a handle and open/close lease. Cooperative monotonic deadline checked around stream reads/writes; remaining timeout passed to adapter. Blocking inbound/outbound socket, authority and resolver deadlines are not guaranteed by this wrapper; production connector, pool, spool, transport, rate and timeout configuration under #16/#42/#43. Adapter resource budgets must match gateway budgets. No in-flight revocation/cancellation claim. Client disconnect may leave uncertain provider effects; reconcile before retry.
- HTTP surface draft contract: [transfer-v1](../../contracts/openapi/transfer-v1.yaml). Separate from control-plane /v1 metadata contracts. No provider IDs/locators returned. No raw header/body logging. Existing metadata advice must not append error JSON after response commit in combined profile.
