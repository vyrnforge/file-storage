JdbcCompletionWork uses existing V3 ledger and V6 evidence, no new migration. Worker loads exact current session/claim/pin and local grant; no persisted bearer. IntegrityReader shared with synchronous verifier to avoid duplicate measurement logic; bounded HEAD/GET exact SHA-256, lease and cooperative time budget. Existing matching evidence can be reused, scan re-hashes full bytes. Atomic final transaction rechecks exact resource, local grant, live claim; writes V6 evidence, finishes VERIFY_UPLOAD, enqueues SCAN_UPLOAD and moves states to VERIFYING with required intents; any failure rolls back all. Stale claim cannot commit. No unsafe overwrite/reissue. Scan worker retains V7 fail-closed state rules.
