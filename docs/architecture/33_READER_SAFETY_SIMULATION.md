# FS-310A4 — Durable reader safety and simulated execution

Status: owner-authorized isolated candidate; PR #83 accepted/merged 65b6ec4, CI 43779802955 passed 187 tests. #36. No physical purge, production retention/hold/quota policy or deployment.

## Reader lifecycle

V14 creates a reader record atomically with each durable download claim, under the same file shared lock as the existing claim. Token is internal, UUIDv7, never returned in HTTP/logging; one per single-use handle. Lease expires at the already bounded handle expiry; gateway cooperative monotonic deadline is additionally bounded by remaining lease duration (no renewal). Only successful exact byte transfer followed by successful provider stream and resolver lease close yields a positive acknowledgement. The gateway acknowledges with exact tenant/file/version/token; idempotent replay is read-only. Late acknowledgement is allowed because actual positive completion is evidence, not expiry. Any failure, crash, uncertain close or acknowledgement outage leaves the reader unresolved. No inferred drain from handle expiration or missing claims. V14 backfills historical claims with no token, permanently unresolved pending separately approved reconciliation; mixed-version untracked claims also block. Retain claimed handles/reader evidence, no automatic reader GC. No public ack API. No hard remote I/O cancellation guarantee: production transport timeout, connection teardown and provider profile evidence remain gates.

## Simulated execution

Separate fs.purge_simulation keyed to V13 operation ID; never in fs.storage_operation, no provider resolver or worker runtime registration. Internal explicit claim with tenant and operation, lease 1ms..5min and max attempts 1..10 as engineering bounds, not production defaults. Claim and completion acquire file lock and revalidate exact original clean version/placement/digest/size, deletion generation, current locked evidence and immutable preparation snapshot; all claimed downloads across generations must have positive drain. No external consumer grant is fabricated: this is a trusted internal simulation, not a new authorization or approval. A single claim wins; expiry allows bounded reclaim with new token/attempt, stale token cannot complete. Completion CAS and Kernel audit/outbox atomic, result SIMULATED only; terminal immutable. Restore invalidates pending simulation eligibility; a historical simulated result never authorizes future work. No provider effects or physical state transitions; V13 and V11 hard gates unchanged. Exhaustion leaves a blocked record, no automatic redrive.
