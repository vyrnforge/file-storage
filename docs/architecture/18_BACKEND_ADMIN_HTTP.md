## Boundaries
- SecuredBackendAdmin uses shared AccessAuthentication, distinct platform subject binding and Kernel tenantless context. LIST/REGISTER require explicit global permissions; READ, REGISTER_LOCATION, REVISE_CREDENTIAL, VALIDATE, ACTIVATE, DRAIN, RETIRE require exact backend ID and action. Tenant header rejected; tenant membership, policy admin or consumer privileges do not confer platform authority. No implicit superuser. Only USER actors; real platform roles, separation of duties and revocation policy are owner/security decisions. Authority failure denies.
- BackendAdminHttpConfiguration is explicit and shares HttpBoundaryConfiguration (API/COMBINED only, metadata admission, neutral errors). Default executable remains loopback health-only, readiness 503. BackendAdminRoutes delegates to BackendAdministration, which composes JdbcRegistry/JdbcConfiguration with injected target allowlist and validator. Server approves exact canonical targets at registration and rechecks for validation. No caller-supplied validator report, approved target list, or raw credential. Credential reference syntax is not proof of immutable authorized secret binding; concrete authority remains #16/#27/#28. Input records redact toString; request body logging forbidden. Responses expose logical IDs, provider, status, revision only, not private endpoint, bucket, prefix or credential reference.
- Existing registry and lifecycle invariants retained: initial location set only before validation, append credential draft via latest CAS, exact validated activation, one-way drain, guarded retirement and atomic intents. Validate uses the existing complete exact report and post-probe snapshot check. Actual DNS/egress/TLS/provider/credential evidence and validator deadlines remain gated. No change to underlying revision selection semantics or migration; review stale/superseded draft activation and evidence lifetime as part of #28 before production.
- Shared query parsing is reused by policy and backend routes. No public API, deployment or new runtime dependency/migration.

## Draft contract
[OpenAPI backend-admin-v1.yaml](../../contracts/openapi/backend-admin-v1.yaml) (JSON is valid YAML). Base /v1/admin/backends: GET bounded discovery and POST register; /{backendId}/active, /revisions, /locations GET; /locations, /credentials, /validate, /activate, /drain, /retire POST. Global list/registration; exact backend permission on all other operations. Metadata JSON 16 KiB max, bearer and optional correlation, no tenant header. after UUID exclusive for lists, before revision exclusive (0 first), limit default 50 max 100. Registration accepts exact approved canonical target, opaque ref only; no secret materials. CAS operations return new revision or neutral conflict; no admin idempotency or retry guarantee. No physical location read API, secret management, object deletion or provider I/O in tests.
