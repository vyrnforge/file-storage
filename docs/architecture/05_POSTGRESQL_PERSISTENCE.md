# FS-120A — PostgreSQL persistence contract

Owner directed next after PR #10 merged. Scope: initial durable metadata and existing initiation/read use cases only. Source main 37a49f3c2488d919ebfeb7f53933c552e499d91b; Kernel v0.3.2. No production database/deployment.

## Decisions
- PostgreSQL 17 disposable test instance; exact production major and operations settings later. Flyway 13.12.1, pgjdbc 42.7.14, Testcontainers 1.21.4 aligned with Kernel v0.3.2 parent. Separate service schema fs and migration location classpath:db/filestorage; no baseline-on-migrate or clean. Migrations invoked explicitly with a trusted DataSource, not automatic production startup. Kernel JDBC migrator uses db/migration and its own reliability tables; integrate later with separate history/schema planning.
- Backend physical identity and location immutable by DB trigger, separated from credential/config revisions, immutable revision keys and policy scope/revisions. Active backend revision and active policy pointer resolved in a consistent repeatable-read transaction. Configuration mutation API, activation CAS, drain/retire enforcement and credential rotation orchestration are later work. Test data only seeded by SQL.
- File, version, session, request identity stored as four related rows. Tenant-bearing composite foreign keys reject cross-tenant links; file ID globally unique opaque max 512 characters. Version/session IDs UUID; location + object key unique. Session pins exact backend/config and policy/location, including foreign keys to historical revisions. No actual object I/O. No runtime lifecycle transition writes; initial states constrained by V1 until later explicit migrations. Existing API supports initiation and reads only.
- Tenant UUIDv7 checked by domain and DB; actor/consumer/purpose/request key technical max 128 characters each (index bounds); filename/mime max 512/255 characters, object key max 1024 UTF-8 bytes. These are implementation bounds, not quota/retention policy. SQL invalid inputs fail with neutral codes. PostgreSQL timestamp precision microseconds; expiry persisted as timestamp plus nano remainder to preserve the existing exact session contract. No expiry/cleanup worker.
- Repeatable-read synchronous transaction: no auto retry; callback failure rolls back; unique request identity prevents duplicates. Concurrent conflict/serialization failure is retryable by caller, not transparent replay; FS-120B will integrate Kernel lease/fingerprint semantics and concurrency/replay guarantees. No new generic idempotency store. Only internal request identity for current application contract. No network calls inside JDBC callback. No provider credentials stored; opaque credential ref only.
- Authorization remains through existing facade/ports; database tenant-scoped queries are defense-in-depth, not RLS or complete production authorization. Grant schema groundwork only; authority sourcing, administration, transaction revocation and live IAM still pending. No tenant admin override.
