# FS-310A11 — Execution-boundary hardening

Status: candidate, CI/owner review pending. A10 PR #94 accepted, merge 69c77b2803f239e255baef6a1ba652f00616ff40, exact-head CI 43821134184 passed 207 tests. Refs #13/#16/#33/#35/#36.

## Audited command boundary

V21 adds explicit principal execution_mode DISABLED (default for existing V19/V20 mappings), REHEARSAL or AUDITED. The V20 wrapper requires AUDITED. DISABLED denies capture, review and inspection, including replay; existing raw functions still serve explicitly provisioned rehearsal principals; if an AUDITED login accidentally inherits raw execution, deferred source-row checks require the matching V20 receipt before commit. V20 receipt checks still require exact Kernel audit/outbox evidence. Source functions hold the mapped principal row lock until commit. No implicit upgrades or retrospective audit; an existing V20 principal must be explicitly re-provisioned by the owner before using the audited wrapper after V21. Historical receipts are retained. Existing raw replays do not create evidence. A mapped principal is still a trusted login; Kernel writer privileges can fabricate unrelated intent records. No production role or grant creation. Owner, superuser, DDL, restore and direct privileged table writes outside boundary.

## Worker execution

V21 moves existing integrated-quota settlement trigger to SECURITY DEFINER with fixed search_path and revoked PUBLIC execution. Existing state transition logic unchanged; disposable non-owner worker loses direct ledger settlement UPDATE, fence INSERT/UPDATE and touch function execution, but retains required SELECT for deferred checks. Six lock-only identity columns are explicitly immutable (file ID, request/session ID, integrity/session ID, handle/session ID, backend revision/backend ID, grant ID). Backend endpoint existing guard remains. Worker still trusted across tenants, with state/operation/evidence writes and Kernel intent privileges; not RLS or hostile-writer isolation. No provider I/O or new executable operations.

## Verification and readiness

Dedicated regressions: accidental raw grant cannot commit new audited capture/review; disabled principal denied raw and audited replay; rehearsal principal denied wrapper; legacy raw result cannot be silently audited; explicit identity change rejected; concurrent duplicate scan finish has one winner and stale replaced claim cannot settle; concurrent recovery has one winner, exact charge/release and outbox counts. A10 rollback regressions use narrower grants. Populated V18 → V20 → V21 migration/repeat rehearsal preserves existing upload/idempotency and legacy principal mapping, defaults to DISABLED, creates no manifest/intent/ledger rows. CI pending. Production readiness requires independent runtime/worker/manifest/dispatcher/owner roles and credential lifecycle, removal of raw grants from audited logins, review of effective inherited grants, production-sized migration rehearsal on populated V20, operational contention/load evidence, monitoring and backup/restore procedures. No actual historical backfill, production limits/durations, hold release, provider deletion or deployment; PR #87 excluded.
