## Composition
RegistryTransferProviderResolver implements the existing gateway port using JdbcRegistry.resolveExisting. The exact authorized backend/config revision/location is queried from the registry (ACTIVE or DRAINING, exact validation), never substituted with the latest revision. New registry overload applies an exact canonical target allowlist and adapter availability predicate after the DB transaction and before external credential lookup. Existing trusted internal registry overload remains unchanged for existing callers. The resolver checks returned backend/location/revision and namespace, then chooses the factory by the persisted provider enum. No caller-supplied endpoints, runtime plug-ins or fallback. Factory is trusted reviewed deployment code, bound to the supplied target/location/revision and credential. It owns partial construction cleanup; resolver owns credential and adapter leases, closes both on normal/failure paths, idempotent close, neutral errors. No provider SDK types in runtime main sources; S3 module test-scope dependency only. No provider/credential calls while holding a DB transaction. Production factory, secret-store implementation, exact DNS/TLS/egress evidence, per-location admission and evidence freshness remain gates. Resolver checks current registry snapshot, not instantaneous revocation/cancellation during transfer. Existing durable pending file/session pins prevent retirement under V4; no new lifecycle policy.
