## Implementation
Nimbus JOSE+JWT 10.10, pinned, Apache-2.0 ([Maven Central](https://central.sonatype.com/artifact/com.nimbusds/nimbus-jose-jwt/10.10)); mature JWT/JWK parser and RSA verification, no hand-rolled crypto. Security module only. Explicit allowed RSA algorithms, exact issuer and singleton audience/client_id, required iat/exp, strict time validity, configured max token lifetime, optional nbf, reject unsupported critical/header key references, delegation/sender-constrained claims. Token length bounded; signature verified before interpreting claims. No token or error detail in exceptions. No roles/scope/tenant claims used for authorization. Verified access maps to existing SecuredFiles facade; no ID or authentication-time inference.

Trusted key source supplies an issuer-bound JWKS snapshot and acquisition time from server-controlled config. Verifier bounds size/count/age, rejects duplicate/missing key IDs, private/weak/non-signing keys, unknown kid, alg mismatch and invalid signatures. Rotation: new trusted snapshot can include current+retained keys, removal denies old tokens. Source unavailable/stale fails closed. Snapshot provider is NOT a live HTTP JWKS client: deployment must obtain authentic HTTPS JWKS from pinned issuer metadata/endpoint, bounded time/size, TLS validation, no untrusted redirect or token-controlled endpoint, safe refresh cadence/rotation, no fallback to untrusted cache; separate verification required. Configured lifetime/age policy must be reviewed before runtime. No live keys or credentials in repo.
