## 2. Architecture invariants: retain these, do not rewrite for style

- Keep one modular product with API/transfer/worker role separation, and unchanged module boundaries: domain -> application contracts -> security/persistence infrastructure -> runtime composition; S3 and native OSS SDKs remain confined to provider adapters (except reviewed factory entrypoints).
- Keep Kernel FileReference and logical file identity independent of bucket/key, physical placement, policy switching and credential rotation.
- Keep exact tenant/actor/consumer/file grant checks, request-local context establishment, replay reauthorization, revocation and deny-by-default semantics.
- Keep one supplied JDBC connection for atomic metadata, audit/event intents and idempotency; never move object-store or external calls into that DB transaction, or split it across multiple repositories/connections.
- Keep exact backend/config-revision/location credential admission **before** secret lookup, old pinned reads after rotation, restricted role separation, lease/fencing, worker recovery and non-destructive purge gates.
- Keep both OSS and S3 behavior and all approved public API/OpenAPI and migration history intact during any pure cleanup.

Source examples: [FileApplication transaction/authorization contracts](https://github.com/vyrnforge/file-storage/blob/a1903778af1e272ae15c025fe28c4cca369c09af/backend/file-storage-application/src/main/java/io/vyrnforge/filestorage/application/FileApplication.java#L48-L85), [initiation + immutable pin selection](https://github.com/vyrnforge/file-storage/blob/a1903778af1e272ae15c025fe28c4cca369c09af/backend/file-storage-application/src/main/java/io/vyrnforge/filestorage/application/FileApplication.java#L211-L244), [pinned resolver safety](https://github.com/vyrnforge/file-storage/blob/a1903778af1e272ae15c025fe28c4cca369c09af/backend/file-storage-persistence/src/main/java/io/vyrnforge/filestorage/persistence/JdbcRegistry.java#L315-L349).

## 4. Proposed before/after Java designs (design targets, NOT implementation approval)

| Target | Before (observed) | After (proposed) | Required preservation |
|---|---|---|---|
| Capability-based tests | 69 assorted tests in one runtime class; 58 in one persistence class | Separate `UploadClaimIT`, `UploadIntegrityScanIT`, `DownloadTransferIT`, `LifecycleRetentionIT`, `QuotaManifestIT`, `RegistryRevisionIT` and reusable checked disposable fixture(s); names illustrative | Preserve all test cases/assertions, isolated PostgreSQL/MinIO/native OSS runs, no shared mutable fixture leakage or weakened negative paths |
| Initiation persistence | `JdbcTransactions` owns Kernel transaction, `JdbcUnit`, row rehydration and SQL inserts | Narrow transaction adapter plus package-private `FileEntryMapper`, `InitiationUnit` and `PlacementSnapshotReader` on the **supplied connection**; avoid additional repository interfaces where no variation exists | Atomic metadata + Kernel audit/event intents, rollback semantics, lease/idempotency, tenant-pin checks and row state restoration |
| Registry | One `JdbcRegistry` contains commands, validation, reader, credential pin admission | Cohesive command and read helper(s) behind the existing public boundary; credential acquisition stays after registry transaction | Exact (backend, revision, location, ref) admission and lock/fence semantics; no latest fallback |
| Query deadline policy | Several direct `prepareStatement` helpers without uniform explicit per-statement timeouts | Reviewed per-duty statement/lock budget helper, bounded by actual DB settings; test blocked SQL and cancellation | Existing conflict mapping and deadlines, transaction rollbacks, ownership fences; never blindly apply one timeout to all queries |
| Transfer | Cooperative deadline wrapper, direct servlet output calls | Network/server-enforced read/write timeouts plus explicit abort/close handling where supported; verify adversarial stalled peers | No provider locator exposure, one-time handles, bounded concurrency, lease cleanup, streaming integrity and neutral errors |
| Security boundary | Dense per-call binding/entitlement/pipeline/grant flow in `SecuredFiles` | Explicit request-local `VerifiedCaller` and named validation stages if warranted; keep same injected trusted ports | No reuse of auth decisions or relaxation of tenant/action/resource/availability checks |
| Dependency guard | Exact POM edges plus `import` line scans | Retain existing guard, add compiled dependency tests; reject FQ references across boundaries and SDK leaks | No new microservices, no kernel File Storage import, provider neutral SPI |

Use established patterns deliberately: **Ports & Adapters** for providers/authority, **Unit of Work** for atomic JDBC, **Strategy** for provider-neutral operations, **owned Factory/Lease** for SDK credentials, and request-local **Policy/Authorization** checks. Do not create generic interface trees, service locators or new repositories solely to satisfy a diagram.
