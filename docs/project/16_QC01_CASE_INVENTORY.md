## QC-01 characterization scope and next gate

New (not moved) tests in `TransferDeadlineCharacterizationTest` hold a blocking upload `InputStream.read` and a blocking download `OutputStream.write` against a 100ms cooperative deadline. They demonstrate that the current gateway can occupy its single admission slot past that deadline until the test explicitly releases I/O, then **must** release the lease/stream, preserve a rejected busy transfer handle and permit recovery. Those **characterization** assertions intentionally describe current behavior and must be replaced by positive hard-deadline assertions when a separately approved QC-02 implementation exists. They prove no real servlet/proxy timeout policy or production resilience. No actual credentials, provider calls or production endpoint.

Additional QC-01 work not yet implemented: deterministic disposable PostgreSQL blocked-statement/lock budget tests, an exhaustive per-test negative-assertion inventory, capability-based physical file splits and CI count reconciliation after the split. The source-reviewed [QC-00/architecture plan](https://github.com/vyrnforge/file-storage/pull/115) remains the approval record; production Java changes need QC-02+ authorization. No new provider, POM, schema, migration, public contract, production role or runtime change.
